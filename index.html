01 · PROBLEM FRAMING

AI 治理的难点，不只是“能不能分类”

真正的治理问题是：什么时候可以相信模型，什么时候必须交给人。 这决定了自动化能走多远，也决定了误伤和漏放风险。

≠

缺少证据

不等于“已经证明虚假”。

“听说某品牌要关闭 30% 门店。”
策略：UNCERTAIN，而不是直接判 FALSE。
≠

没发现风险

不等于“已经证明安全”。

“完整版攻略在主页置顶。”
策略：上下文缺失 → HUMAN REVIEW。
≠

风险信号

不等于“风险事实已经成立”。

高相似度 + 来源已注明 + 授权未知。
策略：Evidence Gate 判断证据充分度。
Project Goal 建立可靠的自动化边界，而不是追求“尽可能多地自动判定”。

05 · HUMAN-IN-THE-LOOP

AI Governance 的终点不是模型输出，而是经验能否回流

将人工裁决结构化为可复用 Case，并自动完成错误归因，为下一轮 Prompt / Rule 提供证据。

01

Review Queue

集中承接 HUMAN_REVIEW、PRIORITY_REVIEW 与 AUTO_PASS_SAMPLE。

02

Human Decision

通过 / 确认风险 / 修改标签 / 无法确认。

03

Case Library

沉淀 Final Label、Reviewer Note、模型输出与人工结论。

04

Error Attribution

CORRECT / FALSE_KILL / MISS / LABEL_MISMATCH / UNCERTAIN_REVIEW。

Key Design

AI = UNCERTAIN，人工最后确认风险，并不等于 MISS

如果模型已经意识到证据不足，并成功把 Case 路由给人工，从治理系统角度，它完成了正确的人机协同。 因此单独定义 UNCERTAIN_REVIEW，避免把“知道自己不知道”错误地统计成漏判。

08 · INSIGHTS

Dashboard 的价值，是告诉我下一步该改什么

当前结果暴露出三个关键治理问题，也形成了下一轮策略优化的明确优先级。

01

模型明显偏保守

False Kill 52.17%

人工最终认为 SAFE 的内容中，大量 Case 被模型判成风险。需要继续区分主观体验 vs 客观宣称、风险信号 vs 风险成立。

02

Auto Pass 仍存在安全风险

Unsafe Auto Pass 11.76%

不能简单降低阈值扩大自动化，否则可能进一步增加误放。Auto Pass 抽检是必须保留的安全护栏。

03

当前仍是 Safety-first

Human Review 57.80%

自动化空间仍大，但扩容前必须先压低误杀和漏放，再逐步提高 Auto Pass Coverage。

Optimization Objective 降低 False Kill，同时不能以提高 Unsafe Auto Pass 为代价。 Safety × Efficiency Trade-off

10 · NEXT ITERATION

从 Case Review 到 V2.1

下一步不再增加系统功能，而是围绕高频错误模式做 Feedback-driven Prompt / Rule 优化，并用独立 Holdout 验证泛化。

Error Patterns
  1. Subjective Puffery 被误判为客观广告宣称
  2. “去主页”被过度推断为商业导流
  3. 缺少证据被直接推断为虚假
  4. AI 透明度覆盖更严重的真实性风险
  5. Multi-label 正确，但 Primary Label 选择冲突
V2.1 Strategy
Evidence Sufficiency Gate Objective vs Subjective Claim Missing Context → UNCERTAIN Primary Label Tie-break AI Authenticity Priority
Final Validation V2 vs V2.1 → 200 new Holdout Cases
Success ≠ Accuracy only False Kill ↓ Unsafe Auto Pass 不升 Risk Recall 保持 UNCERTAIN 边界更稳定
